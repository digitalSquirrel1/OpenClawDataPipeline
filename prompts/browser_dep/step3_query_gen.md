## Query 设计规则

### 核心要求
1. **依赖网页浏览动作**：每个 query 必须依赖和网页交互才能完成。交互动作应尽可能多样和复杂，包括但不限于：
   - 点击链接/按钮/标签页
   - 使用搜索框搜索
   - 选择下拉选项
   - 填写表单
   - 使用日期选择器
   - 分页浏览/翻页
   - 排序/筛选/过滤
   - Ajax 动态内容加载
   - 添加到购物车/收藏夹
   这是 query 必须具备的最重要特征——必须和网页交互才能完成。

2. **依赖网站内容**：query 应依赖一个或多个网站的内容才能回答。需要避免：
   - 人人都知道的常识性信息
   - 大模型预训练阶段通过大量网页数据可以直接回答的信息
   query 要问的是需要实时访问网站才能获取的具体、细节化信息。

3. **必须提及浏览器**：每个 query 中必须明确要求使用浏览器（如"用浏览器..."、"在浏览器中..."、"打开浏览器..."、"通过浏览器..."、"使用 browser..."等）。

4. **控制网站提及比例**：
   - **约 {pct_no_mention}% 的 query 不要直接提及目标网站名称**，让用户需要自己搜索找到合适的网站
   - **约 {pct_mention}% 的 query 可以提到具体网站**（如"用浏览器打开xxx网站，然后..."）

5. **真实具体**：query 必须符合用户画像的身份特征和知识水平，像真实用户在日常工作/生活中会提出的需求。

6. **不依赖多模态信息**：query 不要依赖网页中的图片、视频、音频或纯视觉结构化信息（如图表的视觉样式）。只依赖文本内容和交互元素。

7. **独立完整**：每个 query 必须是独立的、自包含的，不依赖其他 query 的上下文。

8. **可由AI自主完成**：query 描述的任务必须可以由 AI Agent 通过操作浏览器自主完成，不需要中途等待用户输入。
